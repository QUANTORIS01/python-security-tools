## جلسه هفتم: اعتبارسنجی ورودی‌ها (Input Validation) و حملات Injection

# مقدمه

تا اینجای مسیر یادگیری با مفاهیم مهم امنیت آشنا شدیم:

<p dir='rtl'>
• امنیت سایبری چیست <br>
• مهاجمان چه کسانی هستند <br>
• آسیب‌پذیری چیست <br>
• چرخه امنیت چگونه کار می‌کند <br>
• مدل‌سازی تهدید چیست <br>
• احراز هویت و مجوزدهی چگونه کار می‌کنند
</p>

اما اکنون به یکی از خطرناک‌ترین بخش‌های امنیت نرم‌افزار می‌رسیم.

جایی که بسیاری از بزرگ‌ترین نفوذهای تاریخ از آن شروع شده‌اند.

---

# یک قانون طلایی

در امنیت سایبری یک قانون بسیار مهم وجود دارد:

> هر ورودی کاربر را خطرناک فرض کن.

---

# چرا؟

چون شما نمی‌دانید چه کسی در حال ارسال آن ورودی است.

ممکن است:

<p dir='rtl'>
• کاربر عادی باشد <br>
• ربات باشد <br>
• هکر باشد <br>
• بدافزار باشد
</p>

---

# مثال ساده

فرض کنید برنامه شما از کاربر نام دریافت می‌کند:

```python
name = input("Name: ")
```

در نگاه اول همه چیز عادی است.

---

اما هکر می‌تواند چیزی کاملاً متفاوت وارد کند:

```text
'; DROP TABLE users; --
```

یا

```text
../../../etc/passwd
```

یا

```text
&& shutdown /s
```

---

<p dir='rtl' style='font-size:32px; font-wight:bold;'>
Input Validation چیست؟
</p>

<p dir='rtl'>
Input Validation یعنی:
</p>

> بررسی کردن ورودی قبل از استفاده از آن

---

هدف:

برنامه فقط داده‌های معتبر را بپذیرد.

---

# مثال

فرض کنیم IP دریافت می‌کنیم.

ورودی صحیح:

```text
192.168.1.1
```

---

ورودی نامعتبر:

```text
hello
```

یا:

```text
999.999.999.999
```

---

باید قبل از استفاده بررسی شوند.

---

# چرا Port Scanner ما اعتبارسنجی دارد؟

به همین دلیل.

ما در فایل:

```text
validator.py
```

بررسی می‌کنیم:

<p dir='rtl'>
• IP معتبر باشد <br>
• پورت معتبر باشد <br>
• Timeout معتبر باشد <br>
• Workers معتبر باشند
</p>

---

# اگر اعتبارسنجی نکنیم چه می‌شود؟

ممکن است:

<p dir='rtl'>
• برنامه Crash کند <br>
• خروجی اشتباه بدهد <br>
• آسیب‌پذیر شود
</p>

---

<p dir='rtl' style='font-size:32px; font-wight:bold;'>
Injection چیست؟
</p>

<p dir='rtl'>
Injection یعنی:
</p>

> تزریق کردن دستور یا داده مخرب داخل برنامه

---

مهاجم سعی می‌کند کاری کند که برنامه:

به جای اجرای دستور اصلی

دستور مهاجم را اجرا کند.

---

# معروف‌ترین نوع

<p dir='rtl' style='font-size:32px; font-wight:bold;'>
SQL Injection
</p>

---

فرض کنید برنامه این کوئری را می‌سازد:

```sql
SELECT * FROM users
WHERE username='admin'
```

---

برنامه‌نویس اشتباه می‌کند و ورودی کاربر را مستقیم وارد SQL می‌کند.

---

کاربر وارد می‌کند:

```text
' OR 1=1 --
```

---

نتیجه:

```sql
SELECT * FROM users
WHERE username='' OR 1=1 --
```

---

عبارت:

```sql
1=1
```

همیشه درست است.

در نتیجه مهاجم می‌تواند تمام اطلاعات را مشاهده کند.

---

# خطر SQL Injection

ممکن است مهاجم:

<p dir='rtl'>
• اطلاعات کاربران را بخواند <br>
• رمزها را استخراج کند <br>
• داده‌ها را حذف کند <br>
• دیتابیس را نابود کند
</p>

---

# راه حل

استفاده از:

```text
Parameterized Queries
```

یا

```text
Prepared Statements
```

---

مثال:

```python
cursor.execute(
    "SELECT * FROM users WHERE id = ?",
    (user_id,)
)
```

---

<p dir='rtl' style='font-size:32px; font-wight:bold;'>
Command Injection
</p>

نوع دیگری از Injection.

---

فرض کنید برنامه دستور سیستم‌عامل را اجرا می‌کند.

مثال:

```python
import os

os.system("ping " + ip)
```

---

ورودی عادی:

```text
8.8.8.8
```

---

اما مهاجم وارد می‌کند:

```text
8.8.8.8 && shutdown /s
```

---

نتیجه:

```text
ping 8.8.8.8
shutdown /s
```

---

برنامه ناخواسته دستور مهاجم را اجرا می‌کند.

---

# خطر Command Injection

ممکن است مهاجم:

<p dir='rtl'>
• فایل‌ها را حذف کند <br>
• برنامه نصب کند <br>
• کنترل سیستم را به دست بگیرد
</p>

---

<p dir='rtl' style='font-size:32px; font-wight:bold;'>
Path Traversal
</p>

یکی دیگر از حملات رایج.

---

فرض کنید فایل دریافت می‌کنیم:

```text
report.txt
```

---

برنامه:

```python
open("files/" + filename)
```

---

کاربر عادی:

```text
report.txt
```

---

اما مهاجم:

```text
../../../secret.txt
```

---

نتیجه:

برنامه فایل‌های خارج از پوشه مجاز را باز می‌کند.

---

<p dir='rtl' style='font-size:32px; font-wight:bold;'>
XSS چیست؟
</p>

مخفف:

```text
Cross Site Scripting
```

---

این حمله بیشتر در برنامه‌های وب رخ می‌دهد.

---

مثال:

کاربر وارد می‌کند:

```html
<script>
alert("Hacked")
</script>
```

---

اگر سایت این کد را بدون بررسی نمایش دهد:

اسکریپت مهاجم در مرورگر قربانی اجرا می‌شود.

---

# چرا Port Scanner ما کمتر در معرض XSS است؟

چون:

<p dir='rtl'>
• برنامه وب نیست <br>
• HTML تولید نمی‌کند
</p>

اما اگر بعدها نسخه وب بسازیم باید مراقب باشیم.

---

<p dir='rtl' style='font-size:32px; font-wight:bold;'>
Whitelist چیست؟
</p>

بهترین روش اعتبارسنجی.

---

به جای اینکه بگوییم:

چه چیزهایی ممنوع هستند

می‌گوییم:

چه چیزهایی مجاز هستند.

---

مثال

برای پورت:

فقط:

```text
1 تا 65535
```

---

برای IP:

فقط:

```text
IPv4 معتبر
```

---

این روش بسیار امن‌تر است.

---

<p dir='rtl' style='font-size:32px; font-wight:bold;'>
Blacklist چیست؟
</p>

روش ضعیف‌تر.

---

مثال:

```text
این کاراکترها ممنوع هستند:
&
|
;
$
```

---

مشکل:

همیشه راهی برای دور زدن وجود دارد.

---

# چرا Whitelist بهتر است؟

چون فقط موارد شناخته‌شده را قبول می‌کند.

---

# اصل مهم

هرگز به ورودی اعتماد نکن.

حتی اگر:

<p dir='rtl'>
• از فرم سایت آمده باشد <br>
• از API آمده باشد <br>
• از فایل آمده باشد <br>
• از کاربر مدیر آمده باشد
</p>

---

# مثال در پروژه Port Scanner

ما از کاربر دریافت می‌کنیم:

```text
IP Address
Start Port
End Port
Timeout
Workers
```

---

همه این‌ها باید اعتبارسنجی شوند.

---

اگر این کار را نکنیم:

ممکن است:

<p dir='rtl'>
• برنامه کرش کند <br>
• منابع سیستم مصرف شوند <br>
• خروجی اشتباه تولید شود
</p>

---

<p dir='rtl' style='font-size:32px; font-wight:bold;'>
Secure by Default
</p>

یکی از اصول مهم امنیت.

---

یعنی:

> حالت پیش‌فرض باید امن باشد.

---

مثال:

اگر ورودی نامعتبر بود:

```text
Reject
```

نه اینکه:

```text
Guess
```

Logging و Monitoring
