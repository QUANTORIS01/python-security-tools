# جلسه ۶: DNS و نام دامنه

# مقدمه

تا اینجا یاد گرفتیم که برای برقراری ارتباط شبکه‌ای، در نهایت به یک آدرس IP نیاز داریم.

مثلاً:

```text
142.250.190.78
```

اما تصور کن مجبور بودیم برای باز کردن هر وب‌سایت، IP آن را حفظ کنیم.

مثلاً برای ورود به Google باید می‌نوشتیم:

```text
142.250.190.78
```

و برای هر سرویس دیگری هم یک IP دیگر حفظ می‌کردیم.

این کار بسیار سخت است.

راه‌حل:

```text
Domain Name
```

و سیستمی که نام دامنه را به IP تبدیل می‌کند:

```text
DNS
```

---

<p dir='rtl' style='font-size:32px; font-wight:bold'>
Domain Name چیست؟
</p>

<p dir='rtl'>
Domain Name یک نام قابل خواندن برای انسان است که به یک یا چند سرویس یا آدرس اینترنتی اشاره می‌کند.
<?p>

مثال:

```text
google.com
```

یا:

```text
github.com
```

یا:

```text
python.org
```

---

برای انسان:

```text
google.com
```

خیلی راحت‌تر از:

```text
142.250.190.78
```

قابل یادآوری است.

---

<p dir='rtl' style='font-size:32px; font-wight:bold'>
DNS چیست؟
</p>

<p dir='rtl'>
DNS مخفف:
</p>

```text
Domain Name System
```

است.

وظیفه اصلی DNS این است که اطلاعات مربوط به نام‌های دامنه را پیدا کند.

یکی از مهم‌ترین کاربردهای آن:

```text
Domain Name
        ↓
      DNS
        ↓
    IP Address
```

است.

---

# یک مثال واقعی

فرض کن در مرورگر وارد:

```text
google.com
```

می‌شوی.

کامپیوتر باید بداند:

```text
google.com
```

به کدام IP مربوط است.

برای پیدا کردن این اطلاعات، از DNS استفاده می‌شود.

---

# چرا DNS را شبیه دفترچه تلفن می‌دانند؟

تصور کن اسم شخصی را می‌دانی:

```text
Ali
```

اما شماره تلفنش را نمی‌دانی.

در دفترچه تلفن دنبال:

```text
Ali
```

می‌گردی و شماره را پیدا می‌کنی.

<p dir='rtl'>
DNS نیز ایده‌ای مشابه دارد:
</p>

```text
google.com
```

را می‌پرسیم و اطلاعات مربوط به آن را پیدا می‌کنیم.

---

# آیا DNS فقط IP را برمی‌گرداند؟

خیر.

<p dir='rtl'>
DNS فقط یک جدول ساده از:
</p>

```text
Domain → IP
```

نیست.

<p dir='rtl'>
DNS می‌تواند انواع مختلفی از اطلاعات را نگهداری کند.
</p>

به این اطلاعات:

```text
DNS Records
```

می‌گوییم.

---

# رکورد A

رکورد:

```text
A
```

برای نگاشت یک نام دامنه به یک آدرس IPv4 استفاده می‌شود.

مثلاً:

```text
example.com
        ↓
192.0.2.10
```

---

# رکورد AAAA

رکورد:

```text
AAAA
```

برای آدرس IPv6 استفاده می‌شود.

مثلاً:

```text
example.com
        ↓
2001:db8::10
```

---

# رکورد CNAME

رکورد:

```text
CNAME
```

می‌تواند یک نام را به نام دامنه دیگری مرتبط کند.

مثال مفهومی:

```text
www.example.com
        ↓
example.com
```

---

# رکورد MX

رکورد:

```text
MX
```

برای مشخص کردن Mail Server های یک دامنه استفاده می‌شود.

یعنی می‌تواند مشخص کند ایمیل‌های یک دامنه باید به کدام سرورها تحویل داده شوند.

---

<p dir='rtl' style='font-size:32px; font-wight:bold'>
Port Scanner با DNS چه ارتباطی دارد؟
</p>

پروژه فعلی ما مستقیماً IP دریافت می‌کند:

```bash
python -m src.cli 127.0.0.1 1 1000
```

اما در یک ابزار حرفه‌ای‌تر ممکن است کاربر بنویسد:

```bash
scanner example.com 1 1000
```

در این حالت ابتدا باید نام دامنه به اطلاعات مناسب برای برقراری اتصال تبدیل شود.

---

# تبدیل Domain به IP در Python

پایتون ماژول:

```python
socket
```

را در اختیارمان قرار می‌دهد.

یکی از توابع آن:

```python
socket.gethostbyname()
```

است.

---

مثال:

```python
import socket

ip = socket.gethostbyname("example.com")

print(ip)
```

خروجی می‌تواند چیزی شبیه این باشد:

```text
93.184.216.34
```

---

# نکته مهم

نباید تصور کنیم هر دامنه فقط یک IP دارد.

یک دامنه می‌تواند:

<p dir='rtl'>
• چند IP داشته باشد. <br>
• به سرویس‌های مختلف اشاره کند. <br>
• بر اساس موقعیت جغرافیایی پاسخ متفاوتی دریافت کند. <br>
• از IPv4 و IPv6 استفاده کند.
</p>

به همین دلیل ابزارهای حرفه‌ای‌تر معمولاً اطلاعات DNS را دقیق‌تر بررسی می‌کنند.

---

<p dir='rtl' style='font-size:32px; font-wight:bold'>
DNS و Port Scanner
</p>

فرض کن کاربر این را وارد کند:

```text
example.com
```

یک جریان ساده می‌تواند این‌گونه باشد:

```text
example.com
      ↓
DNS Resolution
      ↓
IP Address
      ↓
Port Scan
      ↓
Open Ports
```

---

یعنی:

```text
DNS
```

قبل از:

```text
Port Scanning
```

می‌تواند قرار بگیرد.

---

# یک مثال کامل

فرض کنیم:

```text
example.com
```

به:

```text
192.0.2.10
```

<p dir='rtl'>
resolve شود.
</p>

اکنون اسکنر می‌تواند بررسی کند:

```text
192.0.2.10:22
192.0.2.10:80
192.0.2.10:443
```

---

نتیجه ممکن است:

```text
22  CLOSED
80  OPEN
443 OPEN
```

باشد.

---

<p dir='rtl' style='font-size:32px; font-wight:bold'>
DNS Server چیست؟
</p>

کامپیوتری که به درخواست‌های DNS پاسخ می‌دهد:

```text
DNS Server
```

نام دارد.

---

مثلاً در شبکه ممکن است سیستم تو از DNS Server شرکت اینترنت استفاده کند.

یا می‌توانی از DNS Resolver های عمومی استفاده کنی.

نمونه معروف:

```text
8.8.8.8
```

---

# آیا DNS همیشه روی TCP است؟

خیر.

<p dir='rtl'>
DNS معمولاً از:
</p>

```text
UDP
```

استفاده می‌کند.

پورت معروف DNS:

```text
53
```

است.

---

اما DNS می‌تواند در شرایط خاص از:

```text
TCP
```

نیز استفاده کند.

بنابراین نباید این تصور را داشته باشیم که:

```text
DNS = همیشه UDP
```

---

# چرا این موضوع برای Port Scanner مهم است؟

در تست واقعی پروژه خودمان دیدیم:

```text
53 OPEN domain
```

---

یعنی روی پورت:

```text
53
```

سرویسی مرتبط با DNS در حال اجرا بود.

اما صرفاً دیدن:

```text
domain
```

به این معنی نیست که ما تمام جزئیات سرویس DNS را شناسایی کرده‌ایم.

این همان تفاوت مهم بین:

```text
Service Name
```

و:

```text
Service Detection
```

واقعی است.

---

# تفاوت DNS با Domain

این دو مفهوم را با هم اشتباه نگیریم.

```text
Domain
```

یک نام است.

مثلاً:

```text
example.com
```

---

اما:

```text
DNS
```

سیستم و پروتکل‌هایی است که برای پیدا کردن اطلاعات مربوط به نام‌های دامنه استفاده می‌شود.

# تمرین

برنامه‌ای بنویس که:

<p dir='rtl'>
1. یک Domain دریافت کند. <br>
2. آن را به IP تبدیل کند. <br>
3. IP را نمایش دهد. <br>
4. اگر Resolution با خطا مواجه شد، برنامه Crash نکند.
</p>

مثال:

```text
Domain: example.com
IP: 93.184.216.34
```
