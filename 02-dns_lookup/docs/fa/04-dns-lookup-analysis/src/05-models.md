# فصل چهارم: تحلیل کد پروژه DNS Lookup

## درس ۵: مدل‌سازی داده‌ها با `dataclass`

### ۱. هدف درس

در این درس یاد می‌گیریم:

<div align='right' dir='rtl'>

<span dir='rtl'>• چگونه داده‌های مرتبط را در یک کلاس منظم کنیم.</span> <br>
<span dir='rtl'>• دکوراتور <span dir='ltr'>`@dataclass`</span> چه کدهای تکراری‌ای را حذف می‌کند.</span> <br>
<span dir='rtl'>• ویژگی `frozen=True` چه اثری بر نمونه‌های کلاس دارد.</span> <br>
<span dir='rtl'>• چگونه مدل داده به خوانایی و نگهداری بهتر پروژه کمک می‌کند.</span>

</div>

### ۲. بررسی ساختار فایل `models.py`

کد فایل:

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class DNSRecord:
    """
    Represent a DNS record.
    """
    domain: str
    record_type: str
    value: str
```

این فایل یک کلاس به نام `DNSRecord` تعریف می‌کند که سه ویژگی دارد:

<div align='center' dir='rtl'>

| ویژگی | کاربرد |
|---|---|
| `domain` | نام دامنه مرتبط با رکورد |
| `record_type` |<span dir='rtl'> نوع رکورد DNS</span> |
| `value` | مقدار رکورد |

</div>

هر سه ویژگی با type hint از نوع `str` تعریف شده‌اند؛ یعنی رشته به‌عنوان نوع مورد انتظار آن‌ها مشخص شده است.

این کلاس به‌جای اینکه داده‌ها را در چند متغیر جداگانه نگه دارد، اطلاعات مرتبط با یک رکورد DNS را در یک شیء واحد قرار می‌دهد.

<div align='right' dir='rtl'>

### <span dir='rtl'>۳. <span dir='ltr'>`@dataclass`</span> چه کاری انجام می‌دهد؟</span>

</div>

در پایتون، اگر کلاسی صرفاً برای نگهداری داده‌ها ساخته شود، نوشتن دستی متدهایی مانند <span dir='ltr'>`__init__()`</span> و <span dir='ltr'>`__repr__()`</span> می‌تواند کد تکراری ایجاد کند.

دکوراتور <span dir='ltr'>`@dataclass`</span> این بخش از کار را ساده می‌کند. با توجه به فیلدهای تعریف‌شده در `DNSRecord`، پایتون متدهای متداول لازم برای کار با نمونه‌ها را تولید می‌کند.

برای نمونه:

```python
record = DNSRecord(
    domain="example.com",
    record_type="A",
    value="192.0.2.10",
)

print(record)
```

خروجی به شکلی مشابه زیر خواهد بود:

```text
DNSRecord(domain='example.com', record_type='A', value='192.0.2.10')
```

این نمایش برای بررسی داده‌ها هنگام توسعه و اشکال‌زدایی مفید است.

### ۴. ساخت نمونه از `DNSRecord`

برای ایجاد یک رکورد، کافی است مقادیر سه فیلد هنگام ساخت نمونه مشخص شوند:

```python
record = DNSRecord(
    domain="example.com",
    record_type="MX",
    value="mail.example.com",
)
```

سپس می‌توان به فیلدهای آن دسترسی پیدا کرد:

```python
print(record.domain)
print(record.record_type)
print(record.value)
```

این ساختار خواناتر از نگهداری اطلاعات در چند متغیر نامرتبط است؛ زیرا مشخص می‌کند هر مقدار به کدام رکورد و کدام ویژگی تعلق دارد.

توجه داشته باشید که مقدارهای بالا صرفاً نمونه آموزشی هستند و لزوماً پاسخ واقعی یک درخواست DNS نیستند.

### ۵. مفهوم `frozen=True`

در تعریف کلاس، این عبارت دیده می‌شود:

```python
@dataclass(frozen=True)
```

پارامتر `frozen=True` باعث می‌شود انتساب مقدار جدید به فیلدهای نمونه پس از ساخت آن مجاز نباشد.

برای مثال:

```python
record = DNSRecord(
    domain="example.com",
    record_type="A",
    value="192.0.2.10",
)

record.value = "192.0.2.20"
```

اجرای انتساب آخر باعث ایجاد `FrozenInstanceError` می‌شود.

این ویژگی به حفظ یکپارچگی داده‌ها کمک می‌کند؛ بخش‌های مختلف برنامه نمی‌توانند به‌سادگی مقدار یک فیلد را پس از ساخت نمونه تغییر دهند.

از این ویژگی معمولاً با عنوان **immutable-style data object** یاد می‌شود. با این حال، باید دقت کرد که `frozen=True` به معنای تغییرناپذیری مطلق تمام اشیای درون یک نمونه نیست؛ در این کلاس هر سه فیلد از نوع رشته هستند که خودشان تغییرناپذیرند.

### ۶. آیا `dataclass` نوع داده‌ها را اعتبارسنجی می‌کند؟

خیر. تعریف نوع با `str` به‌تنهایی بررسی نوع در زمان اجرا نیست.

برای مثال، تعریف فعلی به‌خودی‌خود مانع ساخت نمونه با مقداری غیررشته‌ای نمی‌شود:

```python
record = DNSRecord(
    domain=123,
    record_type="A",
    value="192.0.2.10",
)
```

در حالت معمول، این کد فقط به دلیل ناسازگاری `123` با type hint خطای خودکار ایجاد نمی‌کند.

بنابراین، `dataclass` در این فایل وظیفه‌ی مدل‌سازی داده‌ها را انجام می‌دهد، نه اعتبارسنجی کامل محتوای آن‌ها. اعتبارسنجی را می‌توان در لایه‌ای جداگانه یا با منطق مشخصی در خود مدل پیاده‌سازی کرد، اگر نیاز پروژه چنین چیزی را ایجاب کند.

### ۷. نقش مدل داده در معماری پروژه

<div align='right' dir='rtl'>

<span dir='rtl'>`DNSRecord` یک قالب مشخص برای نمایش رکورد DNS ارائه می‌کند. استفاده از چنین مدلی می‌تواند مزایای زیر را داشته باشد:</span>

</div>

<p dir='rtl'>
• نام‌گذاری روشن فیلدهای مرتبط با رکورد <br>
• دسترسی آسان به هر بخش از داده <br>
• نمایش مناسب شیء هنگام اشکال‌زدایی <br>
• جلوگیری از تغییر تصادفی فیلدها پس از ساخت نمونه <br>
• انتقال داده‌ها بین بخش‌های مختلف برنامه با ساختاری مشخص
</p>

با این حال، برای تعیین دقیق اینکه کدام بخش‌های پروژه از `DNSRecord` استفاده می‌کنند، باید فایل‌های مرتبط نیز بررسی شوند. تعریف کلاس به‌تنهایی نشان نمی‌دهد که همه مسیرهای اجرای برنامه از این مدل استفاده می‌کنند.

### ۸. تمرین‌های آموزشی

**تمرین اول — ساخت رکورد**

یک نمونه از `DNSRecord` با مقادیر دلخواه بسازید و هر سه فیلد آن را چاپ کنید.

**تمرین دوم — آزمایش `frozen=True`**

تلاش کنید مقدار `record_type` را پس از ساخت نمونه تغییر دهید. خطای ایجادشده را مشاهده و علت آن را توضیح دهید.

**تمرین سوم — بررسی type hint**

یک نمونه بسازید که در یکی از فیلدهای آن عدد قرار داده شده باشد. توضیح دهید چرا type hint به‌تنهایی مانع این کار نمی‌شود.

**تمرین چهارم — طراحی مدل**

فرض کنید قرار است یک مدل داده برای نتیجه‌ی کامل جست‌وجوی DNS طراحی شود. چه تفاوتی میان یک `DNSRecord` و نتیجه‌ای شامل چند رکورد، وضعیت درخواست و اطلاعات خطا وجود دارد؟

### ۹. جمع‌بندی

در این درس، کلاس `DNSRecord` را بررسی کردیم:

<div align='right' dir='rtl'>

<span dir='rtl'>• <span dir='ltr'>`@dataclass`</span> ساخت کلاس داده‌ای را ساده می‌کند.</span> <br>
<span dir='rtl'>• سه فیلد `record_type`، `domain` و `value` اطلاعات اصلی یک رکورد را نگه می‌دارند.</span> <br>
<span dir='rtl'>• `frozen=True` مانع انتساب مجدد به فیلدهای نمونه پس از ساخت می‌شود.</span> <br>
<span dir='rtl'>• type hintها مستندات نوع مورد انتظارند و به‌تنهایی اعتبارسنجی زمان اجرا را تضمین نمی‌کنند.</span>

</div>

این مدل ساده، پایه‌ای مناسب برای نمایش منظم اطلاعات رکورد DNS فراهم می‌کند.
