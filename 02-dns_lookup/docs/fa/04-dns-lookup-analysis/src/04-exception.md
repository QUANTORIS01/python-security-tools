# فصل چهارم: تحلیل کد پروژه DNS Lookup

## درس ۴: طراحی استثناهای اختصاصی در پایتون (Custom Exceptions)

### ۱. هدف درس

در این درس بررسی می‌کنیم که چگونه می‌توان استثناهای اختصاصی برای یک پروژه تعریف کرد و با استفاده از وراثت، بین خطاهای عمومی و خطاهای خاص رابطه برقرار کرد.

### ۲. بررسی کد `exception.py`

محتوای فایل `src/exception.py`:

```python
class DNSLookupError(Exception):
    pass


class DNSTimeoutError(DNSLookupError):
    pass
```

این کد دو کلاس تعریف می‌کند:

<div align='right' dir='rtl'>

<span dir='rtl'>• `DNSLookupError`: استثنای پایه برای خطاهای مرتبط با ابزار DNS Lookup</span> <br>
<span dir='rtl'>• `DNSTimeoutError`: استثنای اختصاصی برای وضعیت پایان مهلت درخواست DNS</span>

</div>

### ۳. کلاس `DNSLookupError`

```python
class DNSLookupError(Exception):
    pass
```

در پایتون، استثناها معمولاً از کلاس پایه `Exception` یا یکی از زیرکلاس‌های آن ارث‌بری می‌کنند.

در اینجا، `DNSLookupError` به‌عنوان کلاس پایه خطاهای اختصاصی پروژه تعریف شده است.

دستور `pass` به این معناست که بدنه کلاس در حال حاضر عملیات یا ویژگی اضافه‌ای تعریف نمی‌کند. این کار کاملاً معتبر است؛ یک کلاس اختصاصی لازم نیست حتماً متد یا ویژگی جدیدی داشته باشد تا مفید باشد.

وجود این کلاس یک مزیت طراحی دارد: خطاهای مرتبط با DNS می‌توانند زیر یک نوع مشترک قرار بگیرند. در نتیجه، بخش‌های دیگر برنامه می‌توانند در صورت نیاز خطاهای این خانواده را به‌صورت یکجا مدیریت کنند.

### ۴. کلاس `DNSTimeoutError`

```python
class DNSTimeoutError(DNSLookupError):
    pass
```

این کلاس از `DNSLookupError` ارث‌بری می‌کند.

بنابراین، رابطه این دو کلاس به شکل زیر است:

```text
Exception
    └── DNSLookupError
            └── DNSTimeoutError
```

<div align='right' dir='rtl'>

<span dir='rtl'>`DNSTimeoutError` یک نوع خاص از `DNSLookupError` محسوب می‌شود؛ یعنی هر استثنای `DNSTimeoutError` از نظر نوع، عضو خانواده `DNSLookupError` نیز هست.</span>

</div>

این رابطه با استفاده از وراثت برقرار شده و نیازی به بازنویسی رفتار پایه `Exception` ندارد.

### ۵. چرا از استثناهای اختصاصی استفاده می‌کنیم؟

فرض کنید بخش‌های مختلف برنامه با خطاهای مرتبط با DNS مواجه می‌شوند. اگر همه خطاها فقط با پیام‌های متنی مدیریت شوند، تشخیص نوع خطا ممکن است دشوار شود.

استثناهای اختصاصی امکان می‌دهند که برنامه بر اساس نوع خطا تصمیم بگیرد، نه صرفاً متن پیام آن.

برای مثال:

```python
try:
    # اجرای عملیات DNS
    ...
except DNSTimeoutError:
    print("درخواست DNS در مهلت تعیین‌شده کامل نشد.")
```

این قطعه کد صرفاً یک مثال آموزشی از نحوه مدیریت استثناست؛ سه‌نقطه جایگزین عملیات واقعی است.

### ۶. مزیت مهم سلسله‌مراتب استثناها

با توجه به وراثت تعریف‌شده در این فایل، می‌توان خطای خاص و خطای عمومی‌تر را به دو شکل مدیریت کرد.

**مدیریت فقط پایان مهلت:**

```python
try:
    ...
except DNSTimeoutError:
    print("مهلت درخواست DNS به پایان رسید.")
```

**مدیریت همه خطاهای اختصاصی خانواده DNS:**

```python
try:
    ...
except DNSLookupError:
    print("خطایی در عملیات DNS رخ داد.")
```

در حالت دوم، `DNSTimeoutError` نیز گرفته می‌شود؛ زیرا زیرکلاس `DNSLookupError` است.

این ویژگی به برنامه اجازه می‌دهد بسته به نیاز، بین مدیریت جزئی و مدیریت عمومی خطاها انتخاب کند.

### ۷. ارتباط این فایل با `resolver.py`

در فایل `resolver.py`، کلاس `DNSTimeoutError` وارد شده و هنگام دریافت خطای `dns.resolver.LifetimeTimeout` استفاده می‌شود:

```python
except dns.resolver.LifetimeTimeout as exc:
    raise DNSTimeoutError("DNS query timed out") from exc
```

در این مسیر، خطای مشخص کتابخانه `dnspython` به استثنای اختصاصی پروژه تبدیل می‌شود.

استفاده از `from exc` نیز علت اصلی خطا را حفظ می‌کند تا زنجیره استثناها هنگام بررسی خطا در دسترس باشد.

این دو فایل در کنار هم نشان می‌دهند که چگونه می‌توان خطاهای کتابخانه خارجی را به یک رابط خطای متعلق به خود پروژه تبدیل کرد.

### ۸. آیا لازم است هر استثنا پیام اختصاصی داشته باشد؟

خیر. کلاس‌های فعلی با `pass` تعریف شده‌اند و رفتار پایه استثنا را به ارث می‌برند. هنگام ایجاد یک نمونه از این کلاس‌ها، می‌توان پیام دلخواه را به سازنده داد:

```python
error = DNSTimeoutError("DNS query timed out")
print(error)
```

خروجی:

```text
DNS query timed out
```

بنابراین، برای تعریف استثناهای ساده نیازی به نوشتن متد `__init__` نیست؛ مگر اینکه پروژه به رفتار یا اطلاعات اختصاصی بیشتری نیاز داشته باشد.

### ۹. تمرین‌های آموزشی

**تمرین اول — بررسی وراثت**

پیش‌بینی کنید خروجی هر عبارت چیست و سپس کد را اجرا کنید:

```python
error = DNSTimeoutError("Request timed out")

print(isinstance(error, DNSTimeoutError))
print(isinstance(error, DNSLookupError))
print(isinstance(error, Exception))
```

**تمرین دوم — مدیریت عمومی و اختصاصی**

توضیح دهید چرا `except DNSLookupError` می‌تواند `DNSTimeoutError` را نیز دریافت کند.

**تمرین سوم — توسعه طراحی**

فرض کنید قرار است خطایی برای پاسخ نامعتبر DNS اضافه شود. نام مناسبی برای کلاس آن انتخاب کنید و مشخص کنید بهتر است از کدام کلاس ارث‌بری کند. پاسخ را با توجه به سلسله‌مراتب فعلی توضیح دهید.

### ۱۰. جمع‌بندی

فایل `exception.py` با دو کلاس ساده، ساختاری قابل توسعه برای مدیریت خطاها ایجاد می‌کند:

<div align='right' dir='rtl'>

<span dir='rtl'>• `DNSLookupError` کلاس پایه خطاهای اختصاصی پروژه است.</span> <br>
<span dir='rtl'>• `DNSTimeoutError` نوع مشخصی از خطاهای DNS را نمایش می‌دهد.</span> <br>
<span dir='rtl'>• وراثت اجازه می‌دهد خطاها هم به‌صورت اختصاصی و هم در سطح یک خانواده مدیریت شوند.</span> <br>
<span dir='rtl'>• این طراحی وابستگی منطق برنامه به نام استثناهای کتابخانه خارجی را کاهش می‌دهد.</span>

</div>
