# درس نهم: خروجی‌گیری CSV در پایتون

**فایل مورد بررسی:** `src/csv_exporter.py`

## ۱. هدف درس

در این درس یاد می‌گیریم چطور با ماژول استاندارد `csv` در پایتون، داده‌های حاصل از DNS Lookup را در یک فایل CSV ذخیره کنیم.

در پروژه‌ی DNS Lookup، دو روش برای ذخیره‌ی نتایج داریم:

<div align='right' dir="rtl">

<span dir='rtl'>• **JSON:** مناسب برای نگهداری داده‌های ساختاریافته و تبادل داده بین برنامه‌ها.</span> <br>
<span dir='rtl'>• **CSV:** مناسب برای داده‌های جدولی که می‌توان آن‌ها را در نرم‌افزارهای صفحه‌گسترده یا ابزارهای تحلیل داده بررسی کرد.</span>

</div>

## ۲. کد کامل فایل

```python
import csv


def export_csv(data: dict, filename: str) -> None:
    """
    Export DNS results to a CSV file.
    """
    with open(filename, 'w', newline='', encoding='utf-8') as file:
        writer = csv.writer(file)
        writer.writerow(['domain', 'record_type', 'value'])
        for item in data['records']:
            writer.writerow([item['domain'], item['record_type'], item['value']])
```

## ۳. وارد کردن ماژول `csv`

```python
import csv
```

ماژول `csv` بخشی از کتابخانه‌ی استاندارد پایتون است؛ بنابراین برای استفاده از آن نیازی به نصب کتابخانه‌ی جداگانه نداریم.

این ماژول امکاناتی برای خواندن و نوشتن فایل‌های CSV فراهم می‌کند.

<div align='right' dir="rtl">

<span dir='rtl'>CSV مخفف *Comma-Separated Values* است. در این قالب، داده‌ها در قالب ردیف‌ها و ستون‌ها ذخیره می‌شوند و معمولاً مقادیر با ویرگول از هم جدا می‌شوند.</span>

</div>

## ۴. تعریف تابع `export_csv`

```python
def export_csv(data: dict, filename: str) -> None:
```

این تابع دو ورودی دریافت می‌کند:

<div align='right' dir="rtl">

<span dir='rtl'>• `data`: دیکشنری‌ای شامل داده‌هایی که قرار است ذخیره شوند.</span> <br>
<span dir='rtl'>• `filename`: نام یا مسیر فایل خروجی.</span>

</div>

نوع `dict` نشان می‌دهد که انتظار داریم ورودی `data` یک دیکشنری باشد. نوع `str` نیز مشخص می‌کند که نام فایل به‌صورت رشته دریافت می‌شود.

عبارت <span dir='ltr'>`-> None`</span> نشان می‌دهد که تابع برای برگرداندن یک مقدار طراحی نشده است؛ وظیفه‌ی آن نوشتن اطلاعات در فایل است.

نکته: این type hintها به‌تنهایی نوع ورودی‌ها را در زمان اجرا بررسی نمی‌کنند.

## ۵. باز کردن فایل برای نوشتن

```python
with open(filename, 'w', newline='', encoding='utf-8') as file:
```

این خط چند مفهوم مهم پایتون را کنار هم قرار می‌دهد.

<div align='right' dir="rtl">

### <span dir='ltr'>`open()`</span>

</div>

تابع <span dir='ltr'>`open()`</span> فایل را باز می‌کند.

### حالت `'w'`

حرف `w` مخفف *write* است؛ یعنی فایل برای نوشتن باز می‌شود.

اگر فایل وجود نداشته باشد، معمولاً ساخته می‌شود. اگر از قبل وجود داشته باشد، محتوای قبلی آن پاک می‌شود و نوشتن از ابتدا آغاز می‌شود.

بنابراین در صورت نیاز به نگهداری محتوای قبلی، باید از روش دیگری استفاده شود.

<div align='right' dir="rtl">

### <span dir='ltr'>`newline=''`</span>

</div>

در کار با ماژول `csv`، استفاده از <span dir='ltr'>`newline=''`</span> روش توصیه‌شده است. این تنظیم به ماژول CSV اجازه می‌دهد پایان خطوط را خودش مدیریت کند و از ایجاد خطوط خالی اضافی در بعضی محیط‌ها جلوگیری می‌کند.

<div align='right' dir="rtl">

### <span dir='ltr'>`encoding='utf-8'`</span>

</div>

این گزینه رمزگذاری فایل را مشخص می‌کند. UTF-8 برای ذخیره‌ی متن و پشتیبانی از طیف گسترده‌ای از نویسه‌ها مناسب است.

### چرا از `with` استفاده می‌کنیم؟

ساختار `with` تضمین می‌کند که فایل پس از پایان کار، حتی اگر هنگام نوشتن خطایی رخ دهد، به‌شکل مناسب بسته شود.

این روش از باز کردن و بستن دستی فایل مطمئن‌تر و خواناتر است.

## ۶. ساختن CSV writer

```python
writer = csv.writer(file)
```

تابع <span dir='ltr'>`csv.writer()`</span> یک شیء نویسنده می‌سازد که می‌تواند داده‌ها را در قالب CSV داخل فایل بنویسد.

پس از این خط، متغیر `writer` ابزاری برای نوشتن ردیف‌ها در فایل است.

به‌جای اینکه خودمان با اتصال رشته‌ها و افزودن ویرگول CSV بسازیم، از ماژول استاندارد استفاده می‌کنیم. این روش به مدیریت مقادیری که خودشان شامل ویرگول یا نویسه‌های خاص هستند نیز کمک می‌کند.

## ۷. نوشتن سطر عنوان ستون‌ها

```python
writer.writerow(['domain', 'record_type', 'value'])
```

متد <span dir='ltr'>`writerow()`</span> یک ردیف در فایل می‌نویسد.

در این پروژه، ردیف اول شامل سه عنوان است:

<div align='center' dir="ltr">

| domain | record_type | value |
|---|---|---|
| نام دامنه |<span dir='rtl'> نوع رکورد DNS</span> | مقدار رکورد |

</div>

این عنوان‌ها ساختار خروجی را مشخص می‌کنند و خواندن داده‌ها را آسان‌تر می‌سازند.

## ۸. پیمایش رکوردها و نوشتن داده‌ها

```python
for item in data['records']:
    writer.writerow([item['domain'], item['record_type'], item['value']])
```

در این قسمت، تابع به سراغ کلید `records` در دیکشنری `data` می‌رود و روی موارد موجود در آن پیمایش می‌کند.

در هر دور از حلقه:

<div align='right' dir="rtl">

<span dir='rtl'>1. یک رکورد در متغیر `item` قرار می‌گیرد.</span> <br>
<span dir='rtl'>2. مقدار دامنه از `item['domain']` خوانده می‌شود.</span> <br>
<span dir='rtl'>3. نوع رکورد از `item['record_type']` خوانده می‌شود.</span> <br>
<span dir='rtl'>4. مقدار رکورد از `item['value']` خوانده می‌شود.</span> <br>
<span dir='rtl'>5. این سه مقدار با <span dir='ltr'>`writer.writerow()`</span> در یک ردیف جدید نوشته می‌شوند.</span>

</div>

### نمونه‌ی ورودی

فرض کنیم `data` چنین ساختاری داشته باشد:

```python
data = {
    'records': [
        {
            'domain': 'example.com',
            'record_type': 'A',
            'value': '93.184.216.34',
        },
        {
            'domain': 'example.com',
            'record_type': 'AAAA',
            'value': '2606:2800:220:1:248:1893:25c8:1946',
        },
    ]
}
```

و تابع با این فراخوانی اجرا شود:

```python
export_csv(data, 'dns_results.csv')
```

فایل CSV تقریباً چنین محتوایی خواهد داشت:

```csv
domain,record_type,value
example.com,A,93.184.216.34
example.com,AAAA,2606:2800:220:1:248:1893:25c8:1946
```

این مثال فقط شکل داده‌ی خروجی را نشان می‌دهد؛ مقادیر DNS در آن نمونه هستند.

در معماری پروژه‌ی DNS Lookup، فایل `csv_exporter.py` مسئول تبدیل داده‌های آماده‌شده به فایل CSV است.

این جداسازی یک مزیت مهم دارد: منطق جست‌وجوی DNS، ساختاردهی نتایج و ذخیره‌سازی خروجی، هرکدام مسئولیت مشخصی دارند.

همچنین، این تابع به‌جای انجام جست‌وجوی DNS، داده‌های آماده را دریافت می‌کند. در نتیجه می‌توان منطق خروجی‌گیری را مستقل از عملیات شبکه بررسی و آزمایش کرد.

تابع <span dir='ltr'>`export_csv()`</span> انتظار دارد ساختار ورودی شامل کلید `records` باشد و هر رکورد نیز سه کلید `domain`، `record_type` و `value` را داشته باشد. این قرارداد داده‌ای باید هنگام فراخوانی تابع رعایت شود.

## ۱۰. نکات فنی و فرصت‌های بهبود

کد فعلی، خروجی CSV ساده و مشخصی تولید می‌کند. برای توسعه‌های بعدی می‌توان موارد زیر را در نظر گرفت:

<div align='right' dir="rtl">

<span dir='rtl'>• **اعتبارسنجی ساختار ورودی:** اگر `records` یا یکی از کلیدهای مورد انتظار وجود نداشته باشد، تابع خطایی دریافت خواهد کرد. در صورت نیاز می‌توان خطاهای ورودی را مدیریت کرد.</span> <br>
<span dir='rtl'>• **مدیریت خطاهای فایل:** مسیر نامعتبر یا نبود مجوز نوشتن می‌تواند باعث بروز خطا شود. نحوه‌ی مدیریت این خطاها باید با سیاست خطایابی پروژه هماهنگ باشد.</span> <br>
<span dir='rtl'>• **پشتیبانی از فایل‌های بزرگ:** در صورت افزایش حجم داده‌ها، پیمایش و نوشتن ردیف‌به‌ردیف کمک می‌کند تمام رکوردها لازم نباشد هم‌زمان به یک رشته‌ی بزرگ تبدیل شوند.</span> <br>
<span dir='rtl'>• **سازگاری با نرم‌افزارهای صفحه‌گسترده:** در بعضی تنظیمات منطقه‌ای، جداکننده‌ی مورد انتظار ممکن است متفاوت باشد. در صورت نیاز می‌توان جداکننده را در <span dir='ltr'>`csv.writer()`</span> تنظیم کرد.</span>

</div>

این موارد پیشنهادهایی برای توسعه‌اند، نه نشانه‌ی ناکارآمد بودن پیاده‌سازی فعلی.

## ۱۱. تمرین‌های آموزشی

### تمرین اول: بررسی خروجی

دیکشنری نمونه‌ی این درس را به تابع بدهید و فایل CSV تولیدشده را بررسی کنید.

<p dir='rtl'>
• چند ردیف داده در فایل وجود دارد؟ <br>
• عنوان ستون‌ها در کدام ردیف قرار گرفته‌اند؟
</p>

### تمرین دوم: اضافه کردن رکورد

یک رکورد جدید با نوع `MX` به فهرست `records` اضافه کنید و بررسی کنید که تابع آن را نیز در فایل ذخیره می‌کند.

### تمرین سوم: بررسی حالت نوشتن

یک فایل CSV بسازید و داخل آن متنی قرار دهید. سپس تابع را با همان نام فایل اجرا کنید.

بررسی کنید که استفاده از حالت `'w'` چه تأثیری بر محتوای قبلی فایل دارد.

### تمرین چهارم: بررسی ورودی نامعتبر

تابع را با دیکشنری‌ای که کلید `records` ندارد اجرا کنید.

<p dir='rtl'>
• چه خطایی رخ می‌دهد؟ <br>
• چگونه می‌توان پیش از نوشتن فایل، ساختار داده را بررسی کرد؟
</p>
