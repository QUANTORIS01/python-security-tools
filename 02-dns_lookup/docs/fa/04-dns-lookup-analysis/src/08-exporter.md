# فصل چهارم: تحلیل کد پروژه DNS Lookup

## درس ۸: خروجی گرفتن به فرمت JSON در پایتون

### ۱. هدف درس

در این درس یاد می‌گیریم:

<div align='right' dir='rtl'>

<span dir='rtl'>• JSON چیست و چرا برای تبادل داده استفاده می‌شود.</span> <br>
<span dir='rtl'>• چگونه ماژول `json` در پایتون داده‌ها را به JSON تبدیل می‌کند.</span> <br>
<span dir='rtl'>• چگونه با <span dir='ltr'>`open()`</span> و `with` فایل ایجاد یا باز می‌کنیم.</span> <br>
<span dir='rtl'>• نقش <span dir='ltr'>`encoding='utf-8'`</span> و `indent=4` چیست.</span> <br>
<span dir='rtl'>• چرا قابلیت Export از منطق اصلی جست‌وجوی DNS جدا نگه داشته شده است.</span>

</div>

### ۲. بررسی کد `exporter.py`

محتوای فایل:

```python
import json


def export_json(data: dict, filename: str) -> None:
    """
    Export DNS results to a JSON file.
    """
    with open(filename, 'w', encoding='utf-8') as file:
        json.dump(data, file, indent=4)
```

این فایل یک تابع به نام <span dir='ltr'>`export_json()`</span> تعریف می‌کند که دو ورودی دارد:

<div align='right' dir='rtl'>

<span dir='rtl'>• `data`: داده‌ای که باید در فایل ذخیره شود.</span> <br>
<span dir='rtl'>• `filename`: نام یا مسیر فایل مقصد.</span>

</div>

نوع خروجی تابع با <span dir='ltr'>`-> None`</span> مشخص شده است؛ یعنی تابع برای ارائه نتیجه، مقدار بازگشتی مشخصی در نظر نگرفته و کار اصلی آن ذخیره‌سازی داده‌هاست.

<div align='right' dir='rtl'>

### <span dir='rtl'>۳. JSON چیست؟</sapn>

</div>

<p dir='rtl'>
JSON مخفف JavaScript Object Notation است؛ قالبی متنی برای نمایش و تبادل داده‌های ساخت‌یافته.
</p>

برای مثال:

```json
{
    "domain": "example.com",
    "record_type": "A",
    "values": [
        "192.0.2.10",
        "192.0.2.11"
    ]
}
```

این نمونه، اطلاعات یک جست‌وجوی فرضی DNS را در قالبی ساخت‌یافته نمایش می‌دهد.

<p dir='rtl'>
JSON در زبان‌ها و ابزارهای مختلف پشتیبانی می‌شود؛ به همین دلیل، برای ذخیره نتایج و انتقال آن‌ها بین برنامه‌ها مناسب است.
</p>

### ۴. واردکردن ماژول `json`

```python
import json
```

ماژول استاندارد `json` پایتون امکاناتی برای تبدیل داده‌های پایتون به JSON و تبدیل JSON به داده‌های پایتون فراهم می‌کند.

در این فایل، از تابع <span dir='ltr'>`json.dump()`</span> استفاده شده است؛ این تابع داده‌ها را مستقیماً در یک شیء فایل می‌نویسد.

### ۵. باز کردن فایل با <span dir='ltr'>`open()`</span>

```python
with open(filename, 'w', encoding='utf-8') as file:
```

این خط چند بخش مهم دارد.

<div align='right' dir='rtl'>

**`filename`**

</div>

نام یا مسیر فایلی است که داده‌ها در آن ذخیره می‌شوند.

<div align='right' dir='rtl'>

**`'w'`**

</div>

فایل را در حالت نوشتن باز می‌کند. اگر فایل وجود نداشته باشد، معمولاً ایجاد می‌شود؛ اگر از قبل وجود داشته باشد، محتوای قبلی آن جایگزین خواهد شد.

بنابراین، اگر قرار باشد از داده‌های قبلی محافظت شود، باید هنگام طراحی فرایند ذخیره‌سازی به رفتار این حالت توجه کرد.

<div align='right' dir='rtl'>

**<span dir='ltr'>`encoding='utf-8'`</span>**

</div>

کدگذاری متنی فایل را مشخص می‌کند. UTF-8 برای ذخیره متن و نویسه‌های زبان‌های مختلف، از جمله فارسی، مناسب است.

<div align='right' dir='rtl'>

**`with`**

</div>

استفاده از `with` باعث می‌شود فایل پس از پایان بلوک مدیریت‌شده، به‌درستی بسته شود؛ حتی اگر هنگام اجرای عملیات خطایی رخ دهد.

این الگو برای کار با فایل‌ها در پایتون بسیار رایج و توصیه‌شده است.

### ۶. نوشتن داده‌ها با <span dir='ltr'>`json.dump()`</span>

خط اصلی ذخیره‌سازی:

```python
json.dump(data, file, indent=4)
```

تابع <span dir='ltr'>`json.dump()`</span> داده‌های پایتون را به قالب JSON تبدیل کرده و در فایل مشخص‌شده می‌نویسد.

دو آرگومان اصلی آن عبارت‌اند از:

<div align='right' dir='rtl'>

<span dir='rtl'>• `data`: داده‌ای که قرار است ذخیره شود.</span> <br>
<span dir='rtl'>• `file`: شیء فایل بازشده برای نوشتن.</span>

</div>

پارامتر `indent=4` باعث می‌شود خروجی با تورفتگی چهار فاصله‌ای قالب‌بندی شود. این کار خواندن فایل را برای انسان آسان‌تر می‌کند.

برای مثال، JSON فشرده ممکن است به شکل زیر باشد:

```json
{"domain":"example.com","record_type":"A","values":["192.0.2.10"]}
```

با تورفتگی مناسب، همان داده خواناتر می‌شود:

```json
{
    "domain": "example.com",
    "record_type": "A",
    "values": [
        "192.0.2.10"
    ]
}
```

محتوای واقعی فایل به مقداری بستگی دارد که هنگام فراخوانی <span dir='ltr'>`export_json()`</span> به آرگومان `data` داده می‌شود.

### ۷. چه نوع داده‌هایی را می‌توان ذخیره کرد؟

پارامتر `data` در این تابع با type hint از نوع `dict` مشخص شده است. این یعنی دیکشنری به‌عنوان نوع مورد انتظار ورودی معرفی شده است.

ماژول `json` می‌تواند انواع استاندارد قابل‌تبدیل، مانند دیکشنری، فهرست، رشته، عدد، مقدار بولی و `None` را به معادل‌های JSON تبدیل کند.

اما هر شیء پایتون مستقیماً قابل تبدیل به JSON نیست. برای مثال، اگر داده شامل نمونه‌هایی از کلاس `DNSRecord` باشد، نمی‌توان فرض کرد که <span dir='ltr'>`json.dump()`</span> بدون تبدیل اضافی قادر به ذخیره آن‌هاست.

به همین دلیل، داده‌هایی که قرار است صادر شوند باید به ساختاری سازگار با JSON تبدیل شده باشند.

### ۸. ارتباط Export با معماری ابزار

در معماری DNS Lookup، هر بخش مسئولیت جداگانه‌ای دارد:

<div align='right' dir='rtl'>

<span dir='rtl'>• `resolver.py` درخواست DNS را اجرا می‌کند.</span> <br>
<span dir='rtl'>• `results.py` پاسخ‌ها را به اشیای `DNSRecord` تبدیل می‌کند.</span> <br>
<span dir='rtl'>• `formatter.py` نتایج را برای نمایش در ترمینال قالب‌بندی می‌کند.</span> <br>
<span dir='rtl'>• `exporter.py` داده‌های سازگار با JSON را در فایل ذخیره می‌کند.</span>

</div>

جدا بودن `exporter.py` این امکان را می‌دهد که شیوه ذخیره‌سازی تغییر کند، بدون اینکه منطق اجرای درخواست DNS در همین فایل قرار بگیرد.

همچنین، تابع <span dir='ltr'>`export_json()`</span> خودش درخواست DNS اجرا نمی‌کند؛ فقط داده‌ای را که دریافت کرده در فایل می‌نویسد.

### ۹. رفتار خطاها هنگام ذخیره‌سازی

تابع فعلی مدیریت اختصاصی خطاهای فایل را تعریف نکرده است. بنابراین، اگر مسیر مقصد قابل نوشتن نباشد، پوشه مقصد وجود نداشته باشد یا داده قابل تبدیل به JSON نباشد، خطای مربوطه می‌تواند به فراخواننده منتقل شود.

این موضوع لزوماً به معنای ناقص بودن طراحی نیست؛ مدیریت خطا باید متناسب با مسئولیت هر لایه و نیاز برنامه انجام شود. برای مثال، لایه‌ای که فرمان کاربر را اجرا می‌کند می‌تواند تصمیم بگیرد چگونه خطای ذخیره‌سازی را به پیامی قابل‌فهم تبدیل کند.

نکته دیگر اینکه حالت `'w'` محتوای قبلی فایل را جایگزین می‌کند. بنابراین، هنگام استفاده از این تابع باید نام فایل مقصد و رفتار مورد انتظار ذخیره‌سازی مشخص باشد.

### ۱۰. تمرین‌های آموزشی

**تمرین اول — ساخت JSON**

یک دیکشنری ساده شامل دامنه، نوع رکورد و فهرستی از مقادیر بسازید و با <span dir='ltr'>`export_json()`</span> در فایلی به نام `results.json` ذخیره کنید.

**تمرین دوم — تفاوت <span dir='ltr'>`dump()`</span> و <span dir='ltr'>`dumps()`</span>**

در مستندات رسمی پایتون بررسی کنید تفاوت این دو تابع چیست:

<div align='right' dir='rtl'>

<span dir='rtl'>• <span dir='ltr'>`json.dump()`</span></span> <br>
<span dir='rtl'>• <span dir='ltr'>`json.dumps()`</span></span>

</div>

توضیح دهید چرا در فایل فعلی از <span dir='ltr'>`dump()`</span> استفاده شده است.

**تمرین سوم — بررسی فایل خروجی**

پس از ذخیره داده‌ها، فایل JSON را در یک ویرایشگر متنی باز کنید. بررسی کنید که آیا تورفتگی چهار فاصله‌ای اعمال شده است یا خیر.

**تمرین چهارم — رفتار حالت نوشتن**

فایلی ایجاد کنید که محتوایی داشته باشد، سپس تابع <span dir='ltr'>`export_json()`</span> را برای همان فایل اجرا کنید. نتیجه را بررسی کنید و توضیح دهید حالت `'w'` چه اثری بر محتوای قبلی دارد.

### ۱۱. جمع‌بندی

در این درس، تابع <span dir='ltr'>`export_json()`</span> را بررسی کردیم و با چند قابلیت مهم پایتون آشنا شدیم:

<div align='right' dir='rtl'>

<span dir='rtl'>• ماژول استاندارد `json` برای تبدیل داده‌ها به JSON</span> <br>
<span dir='rtl'>• <span dir='ltr'>`open()`</span> برای باز کردن فایل</span> <br>
<span dir='rtl'>• `with` برای مدیریت چرخه عمر فایل</span> <br>
<span dir='rtl'>• <span dir='ltr'>`encoding='utf-8'`</span> برای کدگذاری متن</span> <br>
<span dir='rtl'>• `indent=4` برای خواناتر شدن خروجی</span>

</div>

این بخش از ابزار، امکان ذخیره نتایج را فراهم می‌کند و با جدا نگه داشتن عملیات فایل از منطق DNS، به حفظ ساختار منظم پروژه کمک می‌کند.
