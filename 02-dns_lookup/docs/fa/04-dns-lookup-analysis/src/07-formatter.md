# فصل چهارم: تحلیل کد پروژه DNS Lookup

## درس ۷: قالب‌بندی خروجی در پایتون (Output Formatting)

### ۱. هدف درس

در این درس یاد می‌گیریم:

<div align='right' dir='rtl'>

<span dir='rtl'>• چگونه داده‌های ساخت‌یافته را به متن قابل‌خواندن تبدیل کنیم.</span> <br>
<span dir='rtl'>• چگونه با f-string ستون‌های خروجی ترمینال را مرتب کنیم.</span> <br>
<span dir='rtl'>• چگونه با <span dir='ltr'>`join()`</span> چند خط متن را به یک رشته تبدیل کنیم.</span> <br>
<span dir='rtl'>• چرا بهتر است منطق نمایش خروجی از منطق اجرای درخواست DNS جدا باشد.</span>

</div>

### ۲. بررسی کد فایل `formatter.py`

```python
from src import DNSRecord


def format_dns_results(results: list[DNSRecord]) -> str:
    """
    Format DNS lookup results for terminal output.
    """
    if not results:
        return 'No DNS records found.'

    lines = [f"{'DOMAIN':<30} {'TYPE':<8} {'VALUE'}", '-' * 70]
    for result in results:
        lines.append(
            f'{result.domain:<30} '
            f'{result.record_type:<8} '
            f'{result.value}'
        )

    return '\n'.join(lines)
```

این فایل تابع <span dir='ltr'>`format_dns_results()`</span> را تعریف می‌کند.

تابع یک فهرست از اشیای `DNSRecord` دریافت می‌کند و یک رشته (`str`) برمی‌گرداند که برای نمایش در ترمینال آماده است.

این یعنی تابع مستقیماً درخواست DNS ارسال نمی‌کند و رکورد جدیدی هم نمی‌سازد؛ وظیفه آن، قالب‌بندی نتایجی است که قبلاً آماده شده‌اند.

### ۳. مدیریت حالت بدون نتیجه

ابتدای تابع:

```python
if not results:
    return 'No DNS records found.'
```

در پایتون، فهرست خالی در یک شرط به‌صورت False ارزیابی می‌شود. به همین دلیل، `if not results` حالت خالی بودن فهرست را بررسی می‌کند.

اگر هیچ رکوردی برای نمایش وجود نداشته باشد، تابع پیام زیر را برمی‌گرداند:

```text
No DNS records found.
```

این کار باعث می‌شود حالت بدون نتیجه نیز خروجی مشخص و قابل‌فهمی داشته باشد؛ در نتیجه، تابع به‌جای ساخت جدول خالی، پیام مناسبی برای این وضعیت ارائه می‌کند.

### ۴. ساخت سرستون‌ها و خط جداکننده

خط بعدی:

```python
lines = [f"{'DOMAIN':<30} {'TYPE':<8} {'VALUE'}", '-' * 70]
```

در این قسمت، فهرستی به نام `lines` ساخته می‌شود که ابتدا شامل سرستون‌ها و سپس خط جداکننده است.

عبارت <span dir='ltr'>`'-' * 70`</span> یک رشته شامل ۷۰ خط تیره تولید می‌کند.

در f-string، قالب‌هایی مانند <span dir='ltr'>`:<30`</span> مشخص می‌کنند که مقدار در یک فضای حداقل ۳۰ کاراکتری، به‌صورت چپ‌چین قرار بگیرد.

برای مثال:

```python
print(f"{'DOMAIN':<30} {'TYPE':<8} {'VALUE'}")
```

خروجی، سرستون‌ها را با فاصله‌های مناسب کنار یکدیگر قرار می‌دهد.

<div align='right' dir='rtl'>

<span dir='rtl'>• `DOMAIN` فضای ۳۰ کاراکتری دارد.</span> <br>
<span dir='rtl'>• `TYPE` فضای ۸ کاراکتری دارد.</span> <br>
<span dir='rtl'>• `VALUE` پس از آن‌ها قرار می‌گیرد.</span>

</div>

این شیوه برای مرتب‌سازی متنی ستون‌ها در خروجی ترمینال کاربردی است.

### ۵. افزودن هر رکورد به جدول

حلقه:

```python
for result in results:
    lines.append(
        f'{result.domain:<30} '
        f'{result.record_type:<8} '
        f'{result.value}'
    )
```

تابع روی تمام رکوردهای موجود در `results` پیمایش می‌کند.

در هر دور از حلقه:

<div align='right' dir='rtl'>

<span dir='rtl'>1. مقدار `result.domain` خوانده می‌شود.</span> <br>
<span dir='rtl'>2. نوع رکورد از `result.record_type` دریافت می‌شود.</span> <br>
<span dir='rtl'>3. مقدار رکورد از `result.value` خوانده می‌شود.</span> <br>
<span dir='rtl'>4. یک خط متنی قالب‌بندی‌شده به `lines` اضافه می‌شود.</span>

</div>

استفاده از فیلدهای `DNSRecord` باعث می‌شود کد بتواند اطلاعات هر رکورد را با نام‌های مشخص دریافت کند؛ لازم نیست داده‌ها از روی موقعیت‌های عددی یک فهرست یا اجزای یک رشته استخراج شوند.

همچنین، <span dir='ltr'>`append()`</span> خط جدید را به انتهای فهرست اضافه می‌کند و ترتیب نتایج دریافتی را حفظ می‌کند.

### ۶. تبدیل فهرست خطوط به یک رشته

در پایان:

```python
return '\n'.join(lines)
```

متد <span dir='ltr'>`join()`</span> عناصر یک دنباله متنی را با رشته‌ای که پیش از آن نوشته شده به هم متصل می‌کند.

در این مثال، جداکننده <span dir='ltr'>`'\n'`</span> است؛ یعنی هر عنصر با یک نویسه خط جدید از عنصر بعدی جدا می‌شود.

اگر `lines` به شکل زیر باشد:

```python
lines = [
    "DOMAIN                         TYPE     VALUE",
    "----------------------------------------------------------------------",
    "example.com                    A        192.0.2.10",
]
```

فراخوانی <span dir='ltr'>`'\n'.join(lines)`</span> همه عناصر را در یک رشته چندخطی قرار می‌دهد.

این روش از ساختن رشته خروجی با الحاق‌های متعدد جلوگیری می‌کند و کد را خواناتر نگه می‌دارد.

### ۷. نمونه‌ای از خروجی نهایی

فرض کنید تابع، دو رکورد فرضی دریافت کند:

```python
results = [
    DNSRecord(
        domain="example.com",
        record_type="A",
        value="192.0.2.10",
    ),
    DNSRecord(
        domain="example.com",
        record_type="A",
        value="192.0.2.11",
    ),
]
```

فراخوانی تابع:

```python
output = format_dns_results(results)
print(output)
```

خروجی به این شکل خواهد بود:

```text
DOMAIN                         TYPE     VALUE
----------------------------------------------------------------------
example.com                    A        192.0.2.10
example.com                    A        192.0.2.11
```

مقادیر بالا صرفاً نمونه آموزشی هستند. تابع، داده‌های واقعی ورودی را در همین قالب قرار می‌دهد.

### ۸. چرا قالب‌بندی را از منطق DNS جدا کرده‌ایم؟

در معماری ابزار، این دو مسئولیت مستقل‌اند:

<div align='right' dir='rtl'>

<span dir='rtl'>• `resolver.py` درخواست DNS را اجرا می‌کند.</span> <br>
<span dir='rtl'>• `results.py` پاسخ‌ها را به اشیای `DNSRecord` تبدیل می‌کند.</span> <br>
<span dir='rtl'>• `formatter.py` اشیا را به متن مناسب ترمینال تبدیل می‌کند.</span>

</div>

این جداسازی مزایای مهمی دارد:

<div align='right' dir='rtl'>

<span dir='rtl'>• قالب نمایش را می‌توان بدون تغییر منطق DNS بهبود داد.</span> <br>
<span dir='rtl'>• داده‌های ساخت‌یافته می‌توانند در قالب‌های دیگری مانند JSON یا CSV نیز استفاده شوند.</span> <br>
<span dir='rtl'>• تابع قالب‌بندی به برقراری ارتباط با سرور DNS وابسته نیست.</span> <br>
<span dir='rtl'>• آزمایش قالب‌بندی می‌تواند با ساخت چند شیء `DNSRecord` انجام شود، بدون اینکه هر بار درخواست شبکه اجرا شود.</span>

</div>

به این ترتیب، هر بخش وظیفه مشخصی دارد و توسعه و نگهداری ابزار ساده‌تر می‌شود.

### ۹. نکته درباره عرض ستون‌ها

قالب‌هایی مانند <span dir='ltr'>`:<30`</span> و <span dir='ltr'>`:<8`</span> حداقل عرض ستون را مشخص می‌کنند؛ طول مقدار را محدود نمی‌کنند.

اگر نام دامنه یا مقدار رکورد طولانی‌تر از فضای تعیین‌شده باشد، متن از عرض حداقلی عبور می‌کند و ممکن است ستون‌های بعدی کاملاً هم‌تراز دیده نشوند. این رفتار با قالب‌بندی فعلی سازگار است و برای خروجی متنی ساده معمولاً قابل‌قبول است.

اگر در آینده لازم باشد خروجی برای مقادیر بسیار طولانی نیز کاملاً تراز باقی بماند، می‌توان راهکارهای دیگری برای نمایش جدول در نظر گرفت.

### ۱۰. تمرین‌های آموزشی

**تمرین اول — حالت بدون نتیجه**

تابع را با یک فهرست خالی فراخوانی کنید و توضیح دهید چرا پیام <span dir='ltr'>`No DNS records found.`</span> برگردانده می‌شود.

**تمرین دوم — قالب‌بندی ستون‌ها**

عبارت زیر را اجرا کنید و توضیح دهید <span dir='ltr'>`:<20`</span> چه اثری دارد:

```python
print(f"{'DOMAIN':<20} {'TYPE':<8} {'VALUE'}")
```

**تمرین سوم — استفاده از <span dir='ltr'>`join()`</span>**

فهرست زیر را به یک رشته چندخطی تبدیل کنید:

```python
lines = ["First line", "Second line", "Third line"]
```

سپس نتیجه را چاپ کنید.

**تمرین چهارم — جداسازی مسئولیت‌ها**

توضیح دهید چرا بهتر است <span dir='ltr'>`format_dns_results()`</span> فقط داده‌های آماده را قالب‌بندی کند و خودش درخواست DNS ارسال نکند.

### ۱۱. جمع‌بندی

تابع <span dir='ltr'>`format_dns_results()`</span> یک فهرست از اشیای `DNSRecord` را به متن قابل‌نمایش در ترمینال تبدیل می‌کند.

در این درس با چند قابلیت مهم پایتون آشنا شدیم:

<div align='right' dir='rtl'>

<span dir='rtl'>• شرط `if not results` برای تشخیص فهرست خالی</span> <br>
<span dir='rtl'>• f-string برای مرتب‌سازی ستون‌های متنی</span> <br>
<span dir='rtl'>• <span dir='ltr'>`append()`</span> برای اضافه کردن خطوط به فهرست</span> <br>
<span dir='rtl'>• <span dir='ltr'>`join()`</span> برای ساخت رشته چندخطی</span>

</div>

مهم‌تر از همه، دیدیم که جدا نگه‌داشتن قالب‌بندی از منطق DNS به معماری منظم‌تر و قابل‌گسترش‌تر ابزار کمک می‌کند.
