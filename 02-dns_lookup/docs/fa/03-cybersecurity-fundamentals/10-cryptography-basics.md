# درس ۱۰: مبانی رمزنگاری (Cryptography Basics)

## ۱. رمزنگاری چیست؟

<div align='right' dir='rtl'>

<span dir='rtl'>**Cryptography** یا رمزنگاری، شاخه‌ای از علوم است که روش‌هایی برای محافظت از اطلاعات و ارتباطات ارائه می‌دهد.</span>

</div>

رمزنگاری می‌تواند به ما کمک کند تا:

<p dir='rtl'>
• اطلاعات محرمانه باقی بمانند. <br>
• تغییرات غیرمجاز داده‌ها تشخیص داده شوند. <br>
• هویت یک فرستنده یا سرویس بررسی شود. <br>
• اصالت و تمامیت پیام‌ها تأیید شود.
</p>

برای مثال، وقتی به یک وب‌سایت با HTTPS متصل می‌شویم، از سازوکارهای رمزنگاری برای محافظت از ارتباط استفاده می‌شود.

اما رمزنگاری فقط به HTTPS محدود نیست. این مفهوم در ذخیره اطلاعات، امضای دیجیتال، مدیریت کلیدها و بسیاری از سامانه‌های امنیتی کاربرد دارد.

### اصطلاحات پایه

<div align='center' dir='rtl'>

| اصطلاح | معنی |
|---|---|
| Plaintext | داده قابل خواندن پیش از رمزنگاری |
| Ciphertext | خروجی رمزنگاری‌شده |
| Encryption | تبدیل داده به شکل رمز‌شده |
| Decryption | بازگرداندن داده رمز‌شده به شکل اصلی |
| Key | کلید مورد استفاده در عملیات رمزنگاری |
| Cipher | الگوریتم رمزنگاری |
| Hash | خروجی تابع درهم‌سازی |
| Digital Signature | امضای دیجیتال برای بررسی اصالت و یکپارچگی |

</div>

نکته مهم: **Encryption، Encoding و Hashing سه مفهوم متفاوت هستند.** در ادامه تفاوت آن‌ها را دقیق‌تر بررسی می‌کنیم.

---

<div align='right' dir='rtl'>

## <span dir='rtl'>۲. Encoding چیست؟</span>

</div>

<div align='right' dir='rtl'>

<span dir='rtl'>**Encoding** یا کدگذاری، روشی برای نمایش داده در قالبی مشخص است.</span>

</div>

هدف اصلی Encoding معمولاً محرمانگی نیست، بلکه تبدیل داده به قالبی مناسب برای انتقال، ذخیره‌سازی یا پردازش است.

برای مثال، Base64 داده باینری را به شکلی از متن تبدیل می‌کند که انتقال آن در سامانه‌های متنی آسان‌تر باشد.

فرض کن رشته زیر را داریم:

<div align='right'>

`Hello`

</div>

نمایش Base64 آن چنین است:

<div align='right'>

`SGVsbG8=`

</div>

این تبدیل رمزنگاری محسوب نمی‌شود؛ زیرا هر کسی که قالب Base64 را بداند، می‌تواند داده را به شکل اولیه برگرداند.

### کاربردهای Encoding

<p dir='rtl'>
• انتقال داده‌های باینری در قالب متنی <br>
• نمایش داده در قالب‌های استاندارد <br>
• سازگاری میان سامانه‌های مختلف <br>
• تبدیل متن به نمایش بایتی مشخص
</p>

### نکته امنیتی

اگر اطلاعات محرمانه را فقط با Base64 تبدیل کنیم، آن اطلاعات امن نشده‌اند.

برای مثال، قرار دادن رمز عبور در Base64 هیچ حفاظت رمزنگاری‌شده‌ای ایجاد نمی‌کند.

**قاعده:** Encoding برای نمایش داده است، نه برای محرمانه نگه داشتن آن.

---

<div align='right' dir='rtl'>

## <span dir='rtl'>۳. Encryption چیست؟</span>

</div>

<div align='right' dir='rtl'>

<span dir='rtl'>**Encryption** یا رمزگذاری، فرایندی است که با استفاده از الگوریتم رمزنگاری و کلید، داده قابل خواندن را به داده‌ای تبدیل می‌کند که بدون دسترسی مناسب به کلید و سازوکار رمزگشایی، قابل استفاده مستقیم نباشد.</span>

</div>

هدف اصلی Encryption، محافظت از محرمانگی اطلاعات است.

فرایند کلی را می‌توان این‌طور نشان داد:

<div align='right'>

`Plaintext + Key → Encryption → Ciphertext`

</div>

برای بازگرداندن داده:

<div align='right' dir='rtl'>

`Ciphertext + Key → Decryption → Plaintext`

</div>

برای مثال، فرض کن یک فایل شامل اطلاعات حساس داریم. می‌توانیم آن را با یک الگوریتم رمزنگاری مناسب رمز کنیم تا شخصی که به فایل دسترسی پیدا می‌کند، بدون کلید لازم نتواند محتوای آن را بخواند.

البته امنیت این روش به الگوریتم، نحوه استفاده، مدیریت کلید و سایر جزئیات پیاده‌سازی بستگی دارد.

### رمزنگاری به‌تنهایی همه مشکلات را حل نمی‌کند

اگر مهاجم بتواند کلید رمزنگاری را نیز به دست آورد، ممکن است بتواند اطلاعات را رمزگشایی کند.

همچنین Encryption به‌تنهایی تضمین نمی‌کند که داده تغییر نکرده باشد. برای این هدف باید از سازوکار مناسب تشخیص دست‌کاری نیز استفاده کنیم.

---

## ۴. رمزنگاری متقارن (Symmetric Encryption)

در رمزنگاری متقارن، برای رمزگذاری و رمزگشایی معمولاً از یک کلید مشترک استفاده می‌شود.

فرایند کلی:

۱. فرستنده و گیرنده به کلید مناسب دسترسی دارند.

۲. فرستنده داده را با کلید رمز می‌کند.

۳. داده رمز‌شده منتقل یا ذخیره می‌شود.

۴. گیرنده با کلید لازم آن را رمزگشایی می‌کند.

### مثال: AES

<div align='right' dir='rtl'>

<span dir='rtl'>**AES (Advanced Encryption Standard)** یکی از الگوریتم‌های شناخته‌شده رمزنگاری متقارن است.</span>

</div>

کاربردهای رمزنگاری متقارن شامل موارد زیر است:

<p dir='rtl'>
• رمزنگاری فایل‌ها <br>
• محافظت از داده‌های ذخیره‌شده <br>
• رمزنگاری داده‌های ارتباطی <br>
• محافظت از حجم زیادی از اطلاعات
</p>

### مزیت اصلی

رمزنگاری متقارن معمولاً برای رمزنگاری حجم زیادی از داده‌ها کارآمد است.

### چالش اصلی: مدیریت کلید

فرستنده و گیرنده باید راهی امن برای به‌دست‌آوردن یا اشتراک‌گذاری کلید داشته باشند.

اگر کلید از مسیر ناامن منتقل شود یا در محل نامناسبی ذخیره شود، امنیت اطلاعات ممکن است به خطر بیفتد.

### حالت‌های رمزنگاری و اصالت داده

در استفاده عملی از AES، انتخاب حالت مناسب اهمیت زیادی دارد.

برای رمزنگاری داده‌های جدید، معمولاً استفاده از یک روش **Authenticated Encryption** مانند AES-GCM توصیه می‌شود؛ زیرا هم محرمانگی و هم تشخیص دست‌کاری داده را فراهم می‌کند.

در AES-GCM، استفاده صحیح از Nonce و جلوگیری از تکرار نامناسب آن با یک کلید مشخص بسیار مهم است.

صرف استفاده از نام AES تضمین نمی‌کند که یک پیاده‌سازی امن باشد.

---

## ۵. رمزنگاری نامتقارن (Asymmetric Cryptography)

در رمزنگاری نامتقارن، از یک جفت کلید مرتبط استفاده می‌شود:

<div align='right' dir='rtl'>

<span dir='rtl'>• **Public Key:** کلید عمومی</span> <br>
<span dir='rtl'>• **Private Key:** کلید خصوصی</span>

</div>

کلید عمومی می‌تواند در اختیار دیگران قرار بگیرد، اما کلید خصوصی باید محرمانه باقی بماند.

در کاربردهای رمزنگاری مبتنی بر کلید عمومی، داده‌ای که برای گیرنده رمز می‌شود معمولاً فقط با کلید خصوصی متناظر قابل رمزگشایی است.

این توضیح یک مدل مفهومی است؛ پروتکل‌های واقعی اغلب از روش‌های ترکیبی استفاده می‌کنند.

### کاربردهای رایج

<p dir='rtl'>
• تبادل امن کلید <br>
• امضای دیجیتال <br>
• بررسی هویت سرویس‌ها <br>
• زیرساخت کلید عمومی (PKI) <br>
• ایجاد ارتباطات امن
</p>

### مثال: HTTPS

در ارتباطات HTTPS، از گواهی‌های دیجیتال و سازوکارهای رمزنگاری برای احراز هویت سرویس و ایجاد ارتباط امن استفاده می‌شود.

در پروتکل‌های مدرن مانند TLS، رمزنگاری نامتقارن معمولاً مستقیماً برای رمزکردن تمام داده‌های ارتباط به کار نمی‌رود؛ بلکه سازوکارهای توافق کلید و احراز هویت در کنار رمزنگاری متقارن استفاده می‌شوند.

### تفاوت کلید عمومی و خصوصی

<div align='center' dir='rtl'>

| ویژگی | Public Key | Private Key |
|---|---|---|
| محرمانه بودن | معمولاً می‌تواند منتشر شود | باید محرمانه بماند |
| کاربرد | بسته به الگوریتم، مثلاً رمزگذاری یا بررسی امضا | بسته به الگوریتم، مثلاً رمزگشایی یا ایجاد امضا |
| افشای آن | معمولاً به‌خودی‌خود راز امنیتی محسوب نمی‌شود | ممکن است امنیت سیستم را به خطر بیندازد |

</div>

نکته: در امضای دیجیتال، از کلید خصوصی برای ایجاد امضا و از کلید عمومی متناظر برای بررسی آن استفاده می‌شود. این فرایند با رمزگذاری داده برای محرمانگی یکسان نیست.

---

<div align='right' dir='rtl'>

## <span dir='rtl'>۶. Hashing چیست؟</span>

</div>

<div align='right' dir='rtl'>

<span dir='rtl'>**Hashing** یا درهم‌سازی، فرایندی است که داده با اندازه دلخواه را به خروجی‌ای با اندازه مشخص تبدیل می‌کند.</span>

</div>

تابعی که این کار را انجام می‌دهد **Hash Function** نام دارد.

به‌صورت مفهومی:

<div align='right'>

`Input → Hash Function → Hash Digest`

</div>

برای مثال، می‌توانیم از یک تابع Hash برای محاسبه خلاصه‌ای از محتوای یک فایل استفاده کنیم.

اگر فایل تغییر کند، خروجی Hash نیز معمولاً تغییر می‌کند. این ویژگی می‌تواند برای بررسی یکپارچگی داده‌ها مفید باشد.

### ویژگی‌های مهم تابع Hash رمزنگاری‌شده

یک تابع Hash رمزنگاری‌شده مناسب باید ویژگی‌های امنیتی مهمی داشته باشد، از جمله:

<p dir='rtl'>
• یافتن ورودی‌ای که Hash مشخصی دارد، از نظر محاسباتی دشوار باشد. <br>
• پیدا کردن ورودی دوم با همان Hash ورودی مشخص دشوار باشد. <br>
• پیدا کردن دو ورودی متفاوت با خروجی یکسان دشوار باشد.
</p>

این ویژگی‌ها به‌ترتیب با مفاهیمی مانند مقاومت در برابر پیش‌تصویر، پیش‌تصویر دوم و برخورد (Collision) ارتباط دارند.

### الگوریتم‌های رایج

<p dir='rtl'>
• SHA-256 <br>
• SHA-384 <br>
• SHA-512
</p>

الگوریتم MD5 و SHA-1 به دلیل ضعف‌های شناخته‌شده در مقاومت در برابر برخورد، برای کاربردهای امنیتی جدیدی که به این ویژگی نیاز دارند انتخاب مناسبی نیستند.

### آیا Hash همان Encryption است؟

خیر.

<p dir='rtl'>
Encryption برای رمزگذاری داده طراحی شده و معمولاً امکان بازگرداندن آن با کلید مناسب وجود دارد.
</p>

اما Hashing معمولاً یک فرایند یک‌طرفه است و قرار نیست از روی Hash، ورودی اصلی را مستقیماً بازیابی کنیم.

<div align='center' dir='rtl'>

| ویژگی | Encryption | Hashing |
|---|---|---|
| هدف اصلی | معمولاً محرمانگی | خلاصه‌سازی و پشتیبانی از بررسی یکپارچگی |
| کلید | معمولاً از کلید استفاده می‌کند | تابع Hash معمولی به کلید نیاز ندارد |
| بازگرداندن داده | با سازوکار و کلید مناسب ممکن است | برای Hash معمولی، بازیابی مستقیم هدف طراحی نیست |
| خروجی | داده رمز‌شده | خلاصه یا Digest |

</div>

---

## ۷. چرا Hash کردن رمز عبور با Hash کردن فایل فرق دارد؟

این تفاوت از نظر امنیتی بسیار مهم است.

برای بررسی تغییرات یک فایل، تابعی مانند SHA-256 می‌تواند کاربرد داشته باشد.

اما برای ذخیره رمز عبور کاربران، Hash سریع عمومی مانند SHA-256 به‌تنهایی مناسب نیست.

دلیل این است که مهاجم می‌تواند تعداد زیادی رمز عبور احتمالی را به‌سرعت آزمایش و Hash آن‌ها را با مقادیر سرقت‌شده مقایسه کند.

برای ذخیره رمز عبور باید از روش‌های مخصوص مشتق‌سازی کلید از رمز عبور استفاده کنیم، مانند:

<p dir='rtl'>
• Argon2id <br>
• scrypt <br>
• bcrypt <br>
• PBKDF2
</p>

این روش‌ها به‌گونه‌ای طراحی شده‌اند که آزمایش انبوه حدس‌ها پرهزینه‌تر شود.

<div align='right' dir='rtl'>

### <span dir='rtl'>Salt چیست؟</span>

</div>

<div align='right' dir='rtl'>

<span dir='rtl'>**Salt** مقداری است که به‌صورت یکتا برای هر رمز عبور ذخیره‌شده استفاده می‌شود.</span>

</div>

<p dir='rtl'>
Salt کمک می‌کند رمزهای عبور یکسان لزوماً خروجی ذخیره‌شده یکسانی نداشته باشند و استفاده مجدد از جداول ازپیش‌محاسبه‌شده دشوارتر شود.
</p>

<p dir='rtl'>
Salt لازم نیست مانند رمز عبور محرمانه باشد، اما باید مطابق طراحی الگوریتم تولید و ذخیره شود.
</p>

در عمل، کتابخانه مناسب مدیریت رمز عبور معمولاً تولید و نگهداری Salt را نیز مدیریت می‌کند.

**قاعده:** رمز عبور را به‌صورت متن ساده ذخیره نکن و برای ذخیره آن از Hash سریع عمومی به‌تنهایی استفاده نکن.

---

<div align='right' dir='rtl'>

## <span dir='rtl'>۸. HMAC چیست؟</span>

</div>

<p dir='rtl'>
Hash معمولی به‌تنهایی نمی‌تواند ثابت کند که یک پیام از طرف فرد یا سیستم مورد اعتماد تولید شده است.
</p>

فرض کن مهاجمی بتواند هم یک فایل و هم Hash ذخیره‌شده کنار آن را تغییر دهد. در این صورت، مقایسه ساده Hash ممکن است تغییر را آشکار نکند.

<div align='right' dir='rtl'>

<span dir='rtl'>**HMAC (Hash-based Message Authentication Code)** از یک تابع Hash و یک کلید مشترک استفاده می‌کند تا امکان بررسی اصالت پیام و تشخیص دست‌کاری آن را فراهم کند.</span>

</div>

به‌صورت مفهومی:

<div align='right'>

`Message + Secret Key → HMAC`

</div>

گیرنده‌ای که کلید مشترک معتبر را دارد، می‌تواند مقدار مورد انتظار را محاسبه و با مقدار دریافتی مقایسه کند.

<p dir='rtl'>
HMAC می‌تواند به موارد زیر کمک کند:
</p>

<p dir='rtl'>
• بررسی یکپارچگی پیام <br>
• تأیید اینکه پیام با داشتن کلید مشترک تولید شده است <br>
• تشخیص تغییرات غیرمجاز در داده
</p>

اما HMAC به‌تنهایی محرمانگی ایجاد نمی‌کند؛ برای محرمانگی باید از سازوکار رمزنگاری مناسب استفاده شود.

همچنین چون دو طرف کلید مشترک دارند، HMAC به‌تنهایی مانند امضای دیجیتال اثبات عمومی و قابل‌تفکیک هویت ایجاد نمی‌کند.

---

## ۹. امضای دیجیتال (Digital Signature)

امضای دیجیتال سازوکاری رمزنگاری‌شده برای بررسی اصالت و یکپارچگی داده است.

در مدل متداول امضای دیجیتال:

۱. فرستنده با کلید خصوصی خود امضا ایجاد می‌کند.

۲. پیام و امضا به گیرنده می‌رسند.

۳. گیرنده با کلید عمومی متناظر، امضا را بررسی می‌کند.

اگر بررسی معتبر باشد، می‌توان نتیجه گرفت که امضا با کلید خصوصی متناظر ایجاد شده و داده بررسی‌شده با داده امضاشده مطابقت دارد؛ البته این نتیجه به امنیت کلیدها، الگوریتم و نحوه پیاده‌سازی وابسته است.

### کاربردهای امضای دیجیتال

<p dir='rtl'>
• امضای نرم‌افزار <br>
• تأیید اصالت اسناد دیجیتال <br>
• بررسی صحت بسته‌های نرم‌افزاری <br>
• امضای پیام‌ها <br>
• گواهی‌های دیجیتال و زیرساخت کلید عمومی
</p>

### امضا با Encryption چه تفاوتی دارد؟

امضای دیجیتال و رمزنگاری برای اهداف متفاوتی طراحی شده‌اند.

<p dir='rtl'>
• Encryption عمدتاً برای محرمانگی استفاده می‌شود. <br>
• Digital Signature برای بررسی اصالت و یکپارچگی استفاده می‌شود.
</p>

امضای دیجیتال به‌خودی‌خود محتوای پیام را محرمانه نمی‌کند. اگر پیام باید محرمانه نیز باشد، باید از سازوکار مناسب حفاظت از محرمانگی استفاده شود.

## ۱۰. تفاوت HMAC، Hashing، Encryption، Encoding و Digital Signature

جدول زیر مهم‌ترین تفاوت‌ها را خلاصه می‌کند.

<div align='center' dir='rtl'>

| روش | هدف اصلی | امکان بازگرداندن داده اصلی | کلید |
|---|---|---|---|
| Encoding | نمایش یا انتقال داده | معمولاً بله | معمولاً ندارد |
| Encryption | محرمانگی | با سازوکار و کلید مناسب | دارد |
| Hashing | تولید خلاصه داده و پشتیبانی از بررسی یکپارچگی | بازیابی مستقیم هدف طراحی نیست | Hash معمولی کلید ندارد |
| HMAC | اصالت و یکپارچگی پیام با کلید مشترک | داده را رمز نمی‌کند | کلید مشترک دارد |
| Digital Signature | بررسی اصالت و یکپارچگی | داده را رمز نمی‌کند | کلید خصوصی و عمومی |

</div>

این روش‌ها گاهی در یک سامانه کنار هم استفاده می‌شوند.

برای مثال، یک سامانه می‌تواند داده را رمز کند، روی پیام از HMAC استفاده کند یا برای بسته نرم‌افزاری امضای دیجیتال تولید کند. انتخاب روش مناسب به هدف امنیتی بستگی دارد.

## ۱۱. کار با Hash در Python

کتابخانه استاندارد Python ماژول `hashlib` را برای محاسبه Hashهای رایج در اختیارمان قرار می‌دهد.

مثال:

```python
import hashlib

message = b"Hello, security!"

digest = hashlib.sha256(message).hexdigest()

print(digest)
```

در این مثال:

<div align='right' dir='rtl'>

<span dir='rtl'>• `hashlib` ماژول استاندارد محاسبه Hash است.</span> <br>
<span dir='rtl'>• `message` از نوع `bytes` است.</span> <br>
<span dir='rtl'>• <span dir='ltr'>`sha256()`</span> یک شیء Hash می‌سازد.</span> <br>
<span dir='rtl'>• <span dir='ltr'>`hexdigest()`</span> خروجی را به رشته‌ای از ارقام هگزادسیمال تبدیل می‌کند.</span>

</div>

### چرا از `bytes` استفاده می‌کنیم؟

توابع Hash روی داده‌های بایتی کار می‌کنند.

اگر داده ما رشته متنی باشد، باید آن را به بایت تبدیل کنیم:

```python
text = "Hello, security!"
data = text.encode("utf-8")
```

حالا می‌توانیم `data` را به تابع Hash بدهیم.

### محاسبه Hash یک فایل

برای فایل‌های بزرگ بهتر است محتوا را بخش‌بخش بخوانیم، نه اینکه کل فایل را یک‌جا در حافظه قرار دهیم.

```python
import hashlib


def sha256_file(file_path: str) -> str:
    digest = hashlib.sha256()

    with open(file_path, "rb") as file:
        for chunk in iter(lambda: file.read(8192), b""):
            digest.update(chunk)

    return digest.hexdigest()
```

در این تابع:

<p dir='rtl'>
• فایل در حالت باینری باز می‌شود. <br>
• محتوا در بخش‌های ۸۱۹۲ بایتی خوانده می‌شود. <br>
• هر بخش به شیء Hash اضافه می‌شود. <br>
• در پایان، Hash نهایی برگردانده می‌شود.
</p>

این روش برای فایل‌های بزرگ حافظه کمتری مصرف می‌کند.

### نکته امنیتی

محاسبه Hash به‌تنهایی اصالت فایل را تضمین نمی‌کند.

برای مثال، اگر Hash یک فایل از یک منبع قابل اعتماد دریافت شده باشد، می‌توان آن را با Hash محاسبه‌شده مقایسه کرد.

اما اگر مهاجم بتواند هم فایل و هم Hash مرجع را تغییر دهد، این مقایسه به‌تنهایی کافی نیست. در چنین شرایطی ممکن است به امضای دیجیتال یا سازوکار احراز اصالت دیگری نیاز داشته باشیم.

### DNS Lookup

این مثال نشان می‌دهد که باید مشخص کنیم به کدام ویژگی امنیتی نیاز داریم و سپس کنترل مناسب را انتخاب کنیم.
